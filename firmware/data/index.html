Settings

Changes apply immediately but are lost on restart until saved. Saving stalls the controller for a moment (flash writes pause both CPU cores), so the robot may twitch - best done while it's paused or lying down. Press ? next to any setting for an explanation; double-click a label to reset just that setting.

Drive

Drag to drive: up/down moves, left/right turns. It stops as soon as you let go (or if this page loses its connection).

Xbox controller (Bluetooth)

Pairs an Xbox Wireless Controller (Series X|S, model 1914, or an Xbox One controller with updated firmware) directly with the robot, so no phone is needed. Press Pair, then hold the small pair button on top of the controller until the Xbox logo flashes fast. Only a controller in pairing mode is accepted, and afterwards the robot only connects to that one: just switch it on. Left stick drives (or the right stick turns: Stick layout on the Tune tab); B pauses, A resumes, Y starts a recording (the length set in Record on the Tune tab) or stops one early. It buzzes: twice lightly when it connects, once short when the robot starts balancing, once long when it falls over or is picked up, and once at the start and twice at the end of a recording. Any stick movement takes over from a CAN module.

Wheel spin test (for tuning)

Measures how much the wheels accelerate per amp (the motors' torque constant, which the balance model needs). Lay the robot down so both wheels turn freely, then run it: both wheels get the current forwards, nothing, backwards, nothing, one step each, and it's recorded - download the CSV from Record on the Tune tab. Start small: 0.1 A for 200 ms spins a free wheel up to a few tens of rad/s.

About

Settings on the motor driver boards themselves, changed over CAN (driver firmware 1.1 or later; older firmware is set up over USB serial). Invert and the alignment are pending until Save & reboot, which stops that motor, writes the driver's flash and restarts it. Nothing here works while the robot is balancing - pause it or lay it down first.

Re-run alignment finds the angle between the motor's magnet sensor and its windings again (needed after the motor, magnet or sensor is remounted). The driver reboots twice and the wheel turns a little, so lay the robot on its side or lift that wheel.

Wheels

Each driver board has a CAN node ID (1-15); these choose which boards are this robot's wheels (saved here, nothing changes on the boards). Swap if the wheels respond to the wrong side's commands. Nodes marked "heard" are reporting on the bus now. Change node ID (under a driver) changes the ID saved on that board itself, e.g. to make room for more boards; this robot follows it.

A board with firmware 1.0/1.1 set to "right" is reporting on the bus (ID 0x100). Update it to 1.2 over USB: this firmware sends motor currents in the new format.

      The controller starts FOC on each driver in turn (the wheel twitches during its alignment, unless the driver has a stored alignment), and restarts a driver that resets. After 3 failed starts it gives up; Retry motor start (Tune tab) lets it try again.

      Starting up

      Power onLeave it lying still. WiFi comes up within a few seconds, then the motor drivers start, then the gyro is zeroed (status LED: 3 slow purple flashes, then 3 quick ones when done).
      BalancingStand it upright and hold it still for a moment: it starts once it's within the start angle of the set point and steady, then balances until it tips past the cut-out angle. Lay it down (or let it fall) and the motors switch off. If the wheels spin up (lifted, or after a crash) it stops and waits to be stood up again.
      PauseHolds the motors at 0 A until resumed (not saved: it's balancing again after a restart).
      Low batteryBelow the battery cutoff (Tune tab, System) it stops balancing until the pack is charged or swapped.
      OLEDShows the state, tilt, set point, motor currents and driver states, or a fault screen naming the problem.
